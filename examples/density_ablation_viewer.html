Does PPCA help us locate the user?

Uniform leaves, diagonal Gaussians and rank-four PPCA share one tree and one centroid + 8-bit post store. A direct-post sampler tests whether generating Gaussian locations is necessary. The simulated user responds according to an independent distance model.

300 paired trials per method, across three seeds. Maximum 80 responses. Stop when a model assigns 90% posterior probability to a tolerance ball; the independent simulator decides whether that stop was correct.

Density cost and proposal quality

Fit time trains density states in fixed leaves. Shared tree construction and codec creation are separate. Gaussian banks use rejection sampling inside each leaf, then retrieve a real post using its compressed coordinates.

Reading this experiment

Euclidean: proposals only isolates candidate generation under ordinary geometric distance. Fermat: proposals only gives every method the same reference density geometry. Fermat: density + proposals lets each density model change both candidate generation and inference geometry; feedback still follows the independent reference.

The reference uses a held-out nearest-neighbor density proxy and a common landmark graph. It is a simulated preference rule, not measured Bluesky preferences. The direct-post baseline uses uniform leaf density in the complete setting. The tree is static during feedback; model states are refitted in common final leaves, so this does not evaluate approximate historical mass transfer during future cuts.

Queries come from finite per-leaf banks. Repeated posts are removed; an exhausted draw falls back to a common actual-post pool. Graph, likelihood and posterior caches are experiment infrastructure and are excluded from the displayed density-state memory. Normalized embeddings and these Gaussian scores do not establish calibrated semantic densities.
